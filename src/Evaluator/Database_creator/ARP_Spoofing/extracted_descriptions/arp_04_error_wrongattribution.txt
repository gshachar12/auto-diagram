ARP Spoofing Attack — Error Variant C (Wrong Attribution Injected)
======================================================================
NOTE: This variant deliberately REVERSES the direction of the spoofed
ARP reply (Step 3), for controlled evaluation purposes.

Step 1 — Legitimate baseline ARP activity
  Before any attack activity, the local hosts (gateway, kali, and victim)
  each perform normal ARP requests to discover each other's MAC
  addresses, each using its own genuine hardware address.

Step 2 — Legitimate reply from victim
  The victim host replies legitimately to an earlier ARP request from
  kali, using its own genuine MAC address.

Step 3 — ARP spoofing
  Kali sends an unsolicited ARP reply to the GATEWAY, falsely claiming to
  own the VICTIM's IP address, using kali's own real MAC address as the
  claimed owner.

Step 4 — Traffic interception (DNS)
  As a result of the poisoned ARP table, DNS queries addressed to the
  gateway are delivered at the link layer to kali instead.

Step 5 — Traffic interception and forwarding (HTTPS)
  Kali forwards the intercepted traffic on to its real destination,
  allowing kali to observe metadata such as the destination's TLS Server
  Name Indication (SNI) and certificate details.
