NOTE: Every step below REVERSES which party (client vs. server) initiates
each exchange, relative to the baseline, for controlled evaluation
purposes.

Step 1 — Initial check-in (REVERSED)
  The server sends a "hello" beacon query to the client; the client
  responds with the acknowledgement token.

Step 2 — Network configuration retrieval (REVERSED)
  The server requests network configuration; the client responds with
  tunnel IP, nameserver, port, and subnet information.

Step 3 — Encoding negotiation (REVERSED)
  The server tests character-set/codec support; the client echoes back
  and both settle on encoding algorithms.

Step 4 — Upstream data chunks (REVERSED)
  The server sends data chunks via specially-prefixed queries; the
  client responds with sizeable binary payloads.

Step 5 — Keepalive / polling loop (REVERSED)
  The server polls the client on a steady basis; the client's responses
  carry compressed data down to the server.
